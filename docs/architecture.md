# 아키텍처 및 의사결정 기록

작업하면서 결정한 것들을 그때그때 여기 채워나간다. README를 나중에 몰아 쓰는 대신,
이 파일을 먼저 채우고 README는 여기서 뽑아 정리하는 순서를 권장.

## 시스템 구성

```
[브라우저]
     │ HTTPS
     ▼
┌──────────────── AWS EC2 ────────────────┐
│  Nginx  ─┬─ /      → Next.js  (:3000)   │
│          └─ /api   → NestJS   (:3001)   │
│                          │               │
│                          ▼               │
│                    PostgreSQL (컨테이너) │
└───────────────────────────────────────────┘
```

## 왜 이렇게 결정했나

### 왜 schema.prisma에 datasource url을 안 쓰고 prisma.config.ts로 분리했는가
Prisma 7부터 `datasource.url`을 schema.prisma에 직접 쓰는 방식이 제거되어, DB 연결 문자열은 `apps/api/prisma.config.ts`(CLI용)와 런타임의 `@prisma/adapter-pg` 어댑터(NestJS 코드용)로 옮겨야 한다. `apps/api/.env`의 `DATABASE_URL`은 그대로 두 곳에서 공유해서 읽는다.

### 왜 프론트를 모바일 전용 390px 고정으로 뒀는가
시안(`STIN 자료/디자인 초안 - 무겸`)이 전부 390px 모바일 화면이고, 서비스 사용 맥락도
"세면대 앞에서 폰으로 루틴 확인"이라 데스크톱 레이아웃을 따로 설계할 이유가 없었다.
반응형 분기를 없애면 화면 7개를 만드는 속도가 빨라진다. 데스크톱에서는 390px 프레임을
중앙 정렬하고 뒤에 backdrop만 깐다.

### 왜 다크모드를 지원하지 않는가
시안에 다크 팔레트가 없고, 베이스 `#F4D2E3` / 포인트 `#FF4DC4`가 밝은 톤 전용으로
설계됐다. 다크 팔레트를 새로 만드는 건 학습 목표와 무관한 추가 작업이라 범위에서 뺐다.

### 왜 시스템 폰트 대신 Pretendard를 self-host 하는가
시안은 시스템 폰트 스택이지만, EC2에 CDN 없이 배포하는 구성에서 OS·브라우저마다
한글 렌더링이 갈리는 걸 막으려고 `PretendardVariable.woff2`(SIL OFL-1.1)를 레포에 넣고
`next/font/local`로 로드한다. 폰트 파일 ~2MB는 감수. 동적 서브셋 최적화는 후속 과제.

### 왜 shadcn을 쓰되 컴포넌트는 최소만 가져오는가
Radix 프리미티브 위에 스타일이 얹힌 코드를 복사해오는 방식이라 라이브러리 종속이 없고,
접근성(포커스 트랩·키보드)이 어려운 것만 골라 쓸 수 있다. 화면에 실제로 필요한
컴포넌트만 PR로 추가한다. 상세 규칙은 `docs/design-system.md`.

## 추천 엔진 처리 흐름

```
1. RoutineTemplate 조회 → 단계 구성 + 시간대
2. 단계별 후보 필터링 (피부타입 · 고민 태그 일치)
3. 조합 생성
4. 성분 병용 규칙 검증 (IngredientRule, BLOCK/WARN)
5. 트레이드오프 처리 (해가 없으면 우선순위대로 조건 완화,
   또는 아침/저녁 분리로 해소 시도)
6. 추천 근거 문장 생성
```
